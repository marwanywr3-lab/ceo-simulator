# CEO Simulator — إصدار تطوير 0.2

لعبة محاكاة شركات عربية/إنجليزية ذات خادم مرجعي للاقتصاد. نسخة تطوير منشورة وقابلة للبناء محليًا؛ المتطلبات المتقدمة المتبقية موثقة في تقرير التسليم.

[افتح اللعبة](https://marwanywr3-lab.github.io/ceo-simulator/) · [المستودع](https://github.com/marwanywr3-lab/ceo-simulator)

## التشغيل المحلي

يتطلب Node.js 24 وnpm. من مجلد المشروع:

```sh
npm ci
npm run db:local
npm run api
```

وفي نافذة ثانية من المجلد نفسه:

```sh
npm run dev
```

افتح `http://127.0.0.1:5173/`. أنشئ حسابًا تجريبيًا ببريد وكلمة مرور من 12 حرفًا على الأقل، ثم سجل الدخول وأسّس مسيرة. **لا تُرسل رسالة تحقق ولا يُشترط تحقق بريدي**، طبقًا للتعديل الأخير. لا تستخدم كلمة مرور حقيقية في بيئة التطوير المحلية التي تعمل عبر HTTP. في الإنتاج يلزم HTTPS.

الحساب لمزامنة بيانات المسيرات. تسجيل Google مبرمج لكنه غير مفعّل دون إعداد OAuth. لا توجد خدمة بريد أو استعادة كلمة مرور في هذا الإصدار. تُحفظ جلسة الدخول في الذاكرة ويجب تسجيل الدخول مجددًا بعد إعادة تحميل الصفحة؛ تبقى المسيرات في D1.

## دورة لعب متاحة

1. اختيار الشركة والرئيس التنفيذي والمدينة والقطاع ورأس المال بين 500 ألف و10 ملايين ريال.
2. استئجار مقر، ثم شراء تجهيزات حسب تكلفة القطاع.
3. توظيف مدير من سوق الكفاءات برسوم حقيقية ورواتب دورية داخل اللعبة.
4. تطوير منتج وتحديد سعره؛ التطوير يتقدم مع الوقت والفريق.
5. شراء المواد للقطاعات المادية، ثم بيع المنتج آليًا عند تقدم الأيام.
6. قبول عقد أو تقديم عرض مناقصة، ومتابعة الإنجاز والتحصيل.
7. تمويل الشركة، دفع الفوائد المحاسبية، وسداد أصل القرض.
8. إرسال رسائل وتسجيل اجتماع في ذاكرة الموظفين، وتغيير أسمائهم دون تغيير معرفاتهم.
9. تفويض مدير مؤهل بميزانية تسويق أسبوعية محددة أو إلغاء التفويض.
10. فتح فرع بتكلفة وآثار تشغيلية، وفحص دفتر الأستاذ والتقارير ونقاط الاستعادة.

هذه أنظمة مبسطة موثقة، ولا تتضمن كامل تفاصيل الموارد البشرية والعقود والحوكمة الواردة في الطلب الأصلي. انظر [تقرير التسليم](DELIVERY_REPORT.md).

## الاختبارات

```sh
npm test
npm run check:assets
npm run build
# يتطلب تشغيل API المحلية أولًا

```

اختبارات API تنشئ حسابات تجريبية ومسيرات في قاعدة التطوير؛ لا تشغّلها على قاعدة إنتاج. بيانات تشغيل Wrangler موجودة داخل `apps/api/.wrangler` وغير مضمنة في ZIP أو Git. لا تتقدم المحاكاة عند إغلاق المتصفح أو إيقاف الوقت. التنقل يعالج حدود الأيام أيضًا.

## البنية

- `apps/web`: React، TypeScript، Vite، Zustand، TanStack Query، واجهة RTL/LTR.
- `apps/api`: Cloudflare Worker، المصادقة، التحقق، الأوامر، D1 والحفظ.
- `packages/shared`: مخططات Zod وتعريفات القطاعات والمرشحين.
- `packages/simulation`: محرك حتمي مستقل ودفتر مزدوج القيد، الأموال أعداد صحيحة بالهللات.
- `packages/ai`: حدود أوضاع التوكنات، اختيار الذاكرة، سجل النماذج المؤكدة؛ لا يوجد مزود حي أو حوار AI في هذا الإصدار.
- `database/migrations`: ثلاثة ترحيلات لعشرة جداول مستخدمة وفهارس انتهاء الصلاحية.
- `public/assets`: 140 صورة من الملفات المرفقة، دون أصول المرحلة الثانية أو صور شخصيات.
- `tests`: 21 اختبار وحدات ومحرك و22 فحص API محلي، و9 فحوص ناجحة على API المنشورة.

الحفظ الاقتصادي مجمّع في JSON بإصدار على مستوى المسيرة. اختير لضمان استعادة متسقة ومعاملة ذرية لكل قرار. هذا ليس تنفيذًا كاملًا للمخطط العلائقي المفصل المطلوب؛ فصل الجداول التشغيلية والتقارير الكبيرة إلى علاقات/R2 عمل لاحق. لا توجد جداول صورية فارغة للادعاء بتغطية الأنظمة.

لا تعدّل الواجهة قاعدة البيانات مباشرة. كل أمر يعاد التحقق منه على الخادم. مفتاح الطلب يمنع تكرار التنفيذ، وإصدار الحالة يمنع فقد تحديثات متزامنة. تُحفظ القيود والتوظيف والمنتجات والوقت والذاكرة معًا داخل المعاملة.

## تجهيز Cloudflare

أُنشئت قاعدة `ceo-simulator-production` ونُشر `ceo-simulator-api` في حساب إضافة Cloudflare المختار. فحص Cloudflare أكد الخطة المجانية، ولم تحدث ترقية. عنوان API: https://ceo-simulator-api.marwan-codes-platform.workers.dev . ملف إعداد الإنتاج يتضمن الربط الحقيقي، بينما ملف التطوير يستخدم قاعدة محلية مستقلة. الأوامر التالية للتشغيل اللاحق عبر حساب مفوض:

```sh
npx wrangler login
npx wrangler d1 create ceo-simulator-production
node scripts/configure-production.mjs --database-id=REAL_D1_UUID --origin=https://YOUR_FRONTEND_HOST
npx wrangler d1 migrations apply DB --remote --config apps/api/wrangler.production.jsonc
npx wrangler deploy --config apps/api/wrangler.production.jsonc
```

استبدل `REAL_D1_UUID` بالقيمة التي تعيدها Cloudflare، و`YOUR_FRONTEND_HOST` بنطاق الواجهة الحقيقي فقط؛ سكربت الإعداد يرفض معرفًا غير صالح. لا تنفذ أوامر الإنتاج قبل مراجعة الحساب والموارد. لا تُنشأ R2 أو Queues لأن النسخة الحالية لا تحتاجها، ولتجنب موارد وتكاليف بلا استخدام.

لتشغيل Google: أنشئ OAuth Client من نوع Web لدى Google، وأضف أصل الواجهة إلى JavaScript origins المسموح بها، ثم أضف `--google-client-id=PUBLIC_CLIENT_ID` إلى أمر الإعداد. لا يحتاج مسار GIS الحالي إلى Client Secret. يتحقق Worker من توقيع Google والمُصدر والجمهور والصلاحية وnonce قصير العمر يستخدم مرة واحدة. لا يربط حساب كلمة مرور بحساب Google تلقائيًا اعتمادًا على تطابق البريد. [مرجع Google](https://developers.google.com/identity/gsi/web/guides/verify-google-id-token).

## تجهيز GitHub Pages والأتمتة

أُنشئ المستودع العام https://github.com/marwanywr3-lab/ceo-simulator . تضبط CI الاختبارات والبناء؛ إعداد Pages يستخدم GitHub Actions. إعدادات النشر:

- `ENABLE_PAGES=true` بعد اختيار GitHub Actions في إعدادات Pages.
- `VITE_API_URL`: أصل Worker الفعلي عبر HTTPS، دون `/api` في آخره.
- `ENABLE_WORKER=true` بعد توليد ملف إعداد الإنتاج والتزامه في Git.
- Secrets: `CLOUDFLARE_API_TOKEN` و`CLOUDFLARE_ACCOUNT_ID` داخل إعدادات GitHub فقط.

فحص CI يشغّل الاختبارات وD1 محلية ثم يبني المصدر، ولا ينشر شيئًا. Pages يُبنى تحت `/ceo-simulator/`. ملف `worker.yml` ينشر Worker، ويجب تطبيق ترحيلات D1 قبل نشر نسخة تعتمد عليها. تحقق من نتيجة التشغيل في Actions؛ نشر Worker الآلي يبقى متوقفًا إلى أن يضيف المالك بيانات اعتماد النشر في Secrets. نُشر Worker الحالي عبر اتصال Cloudflare المفوض، واجتاز 9 فحوص HTTPS فعلية مع حذف بيانات الاختبار بموافقة المستخدم.

## الأصول والتطوير اللاحق

المشاهد الأفقية والعمودية ومناطقها محفوظة في `public/assets/01_Offices/assets-manifest.json`. الواجهة تستخدم مناطق مستقلة لكل نسبة أبعاد. الحقول قابلة للتعديل دون تغيير مكوّن المشهد. أزرار الشخصيات عناصر HTML حقيقية، وليست صورًا. باقي الأصول محفوظة للتوسع وليست كلها مستخدمة في مشاهد اللعب الحالية.

ملف `asset-inventory.json` يسرد المقاسات والملفات؛ الفحص آلي لكل الأصول. فُحصت النسخة المنشورة تفاعليًا على سطح المكتب والجوال بالعربية والإنجليزية، بما يشمل التأسيس والتوظيف والذاكرة والتقارير والحفظ والاستعادة ودخول جلسة جديدة. لم يُفحص كل أصل بصريًا، ولا توجد حزمة Playwright آلية شاملة.
